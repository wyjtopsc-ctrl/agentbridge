# 对外表述规范（agentbridge 0.9.3 / 行为审计草案）

本文件是对外材料的统一措辞基线。原则：**先写证据条件，再写能力；先写不证明什么，再写证明什么。**

## 1. 禁止的无条件表述

- “改了能被发现”
- “不可篡改”
- “Agent 不能给自己作证”
- “签名证明谁签的”
- “经过代理 100% 留痕”
- “全量行为审计”
- “不信任发送方也能复核”
- “TEE 证明模型真实输出”
- “跨租户读取能防”
- “锚点证明事件发生时间”

## 2. 替代表述

| 场景 | 表述 |
|---|---|
| 防篡改 | 在指定签名与独立检查点条件下，可发现受覆盖记录的特定改动；未锚定的协同重写不可发现 |
| 身份 | 验证签名与指定密钥的对应关系；主体归属依赖注册、密钥保管和外部信任配置 |
| Agent 自报告 | Agent 的自报告是来源声明，不等于独立观察；审计需要区分来源、观察与收录 |
| 覆盖 | 检查已收录事件及可观测缺口；采集完整性需要独立对账依据，覆盖声明不能证明“没有遗漏” |
| 代理留痕 | 明确持久化成功条件、故障窗口和“结果未知”状态；不承诺经过代理即 100% 留痕 |
| 删除检测 | 对已被独立检查点覆盖的记录，检查删除或改写；锚定前的删除不可发现 |
| 委派阻断 | 在受支持权限模型和不可绕过执行路径内实施检查；绕过网关的调用无法阻断 |
| 模型证明 | 远程证明只支持被测量组件与明确绑定数据的声明；普通签名不证明模型“真实输出” |
| 隔离 | 跨租户隔离属于待实现和验收目标，不是当前能力 |
| 离线核验 | 无需依赖发送方在线服务，但接收方必须独立确认信任配置（公钥、锚点、状态发布者） |
| 锚点 | 锚点应处于独立控制与保管边界；只有具备可信时间依据的锚点，才支持相应时间结论 |

## 3. 三层定位标签

任何对外材料提到“Agent 行为安全审计”时，必须同时标注：

- **已有能力**：Agent 交付与身份的可验证证据组件；
- **试点验证**：Agent 工具调用与交付行为的可验证审计证据；
- **未来方向**：Agent 行为安全审计（不承诺全量覆盖、检测或阻断）。

## 4. 使用规则

- README、白皮书、手册、deck、发布文案、视频字幕统一引用本文件；
- 新表述先加到本文件，再改对外材料；
- 发现旧材料与本文冲突时，以本文和版本化文档为准，不回改冻结历史。
