# ADR-0001：证据包 v0 实现前的四个决定

**状态**：已接受（2026-10-21，用于启动验证性编码）　**决策人**：Lead　**影响**：D1–D4、E1–E3、K1–K4

## 背景

协议已到可执行程度（参考验证器、16 用例、独立密码学校验、Ajv schema 校验），但产品 0.6.1 没有证据包所需的
任务/版本/验收数据模型，且新旧签名规范化不同。开工前必须先固定四个决定，否则会返工在数据模型与规范化上。

## D1 协议版本与旧格式边界

- 新增签名的对象（验收记录、撤销状态、manifest）带 `protocol_version: "0.1"`。
- **旧对象不迁移、不重签**：账本条目按“对 `digest` 字符串签名”验证；信封按 `canon(信封去 signature)`、无域前缀；
  锚点回执按 `canon(回执去 service_sig)`、无域前缀。
- 验证输出记录每条对象使用了哪套规则；禁止用新域验旧记录。
- 旧格式支持范围：**只承诺 0.6.x 已核对发行版**（0.6.1 实测）；更早版本不承诺。

## D2 验收记录的存储形态

- 新增账本条目类型 `accept`，字段：`acceptance_id`、`delivery_id`、`version`、`record_sha256`、`actor`。
- 验收记录是独立文件，按域 `agentbridge-evidence/0.1\nacceptance-record\n` 签名，原始字节保留。
- 证据包引用 `record_sha256` 与原始文件；导出不重签、不改写。
- 拒收（`reject`）同构，`decision` 区分 accepted/rejected。

## D3 撤销状态发布者

- 撤销状态是独立文件，由发布者密钥按域 `.../status` 签名，含 `published_at`、`valid_until`、`revocations[]`。
- 发布者公钥通过**独立渠道**交付给接收方，写入外部信任输入；包内公钥不建立身份。
- 试点期由我方或客户任一方托管发布者；具体由谁运行、公钥如何核对，写入**试点准入条件**，不写进 v0 协议承诺。
- v0 不承诺可信时间戳；受信时间只来自锚点回执（覆盖位置 + `received_at`）或试点约定的外部时间证据。

## D4 证据包导出映射（真实桥 → v0 包）

- v0 只导出**任务单链**：一个交付对象、若干版本、一次验收；不做跨任务批导出。
- 账本导出从 genesis 起的**全量切片**（上限 10 万条），逐字节保留；信封、回执、状态文件逐字节保留。
- `content_mode` 固定 `hashes_only`；附件只导出哈希与字节数，不导出内容。
- `bridge_id` 只存在于锚点回执文件（B7）：manifest 的 anchor 对象通过 `path+sha256` 引用回执，
  验证器用回执内的 `bridge_id` 与外部信任输入的 `expected_bridge_id` 比对。
- 导出不改变账本、不触发写入、不重建 head；只读。

## 后果

- 实现必须先加 `accept` 条目类型与验收记录签名，再做导出与验证；旧的账本/信封验证逻辑保持不变。
- 两套规范化并存是**有意的**：旧对象用旧规则，新对象用 JCS 语义；验证器必须显式分支。
- 若试点要求跨任务导出、内容复核或第三方时间戳，属于 v1 范围，不在 v0 承诺。
